## Главные выводы (минимум 3)

1. **ASP.NET Core позволяет быстро создавать веб-серверы**. Благодаря Minimal API мы можем определить сервер всего в нескольких строках кода, при этом сохраняется высокая производительность и строгая типизация C#.

2. **Middleware даёт мощный контроль над обработкой запросов**. Цепочка middleware позволяет реализовывать сквозные функции — логирование, аутентификацию, сжатие ответов, изменение заголовков — без дублирования кода в маршрутах.

3. **Автоматическая сериализация в JSON** упрощает создание API. ASP.NET Core сам преобразует объекты C# в JSON (с правильным camelCase), что делает фреймворк идеальным для взаимодействия с JavaScript-клиентами.

## Ответы на вопросы

### 1. Чем Minimal API отличается от MVC в ASP.NET Core?

- **Minimal API** — легковесный подход, предназначен для небольших микросервисов и простых HTTP-API. Маршруты определяются лямбда-функциями прямо в `Program.cs`, нет контроллеров, минимум шаблонного кода.
- **MVC** — полноценный паттерн Model-View-Controller. Использует классы контроллеров с методами действия, атрибуты маршрутизации, поддержку представлений (Razor), работает лучше для больших приложений с UI.

### 2. Что произойдёт, если поставить `app.MapGet(...)` до `app.Use(...)`?

`MapGet` (как и `MapPost`, `MapDelete`) регистрирует **терминальное middleware** — оно обрабатывает запрос и возвращает ответ, **не вызывая** последующие `Use`-middleware. Поэтому если разместить `MapGet` до `app.Use`, то middleware логирования, проверки ключа и т.д. **не будут выполнены** для этого маршрута. Порядок регистрации критически важен: сначала middleware, потом маршруты.

### 3. Почему ASP.NET Core преобразует PascalCase в camelCase при сериализации JSON?

Это сделано для соответствия **стандартам JavaScript** и широко принятым соглашениям в веб-API (см. *JSON API convention*). Клиенты на JavaScript ожидают свойства `firstName`, а не `FirstName`. Настройкой можно управлять через `JsonSerializerOptions.PropertyNamingPolicy = null`, но по умолчанию используется `JsonNamingPolicy.CamelCase`.

### 4. Что означает код ответа HTTP 401? А 404? А 200?

- **200 OK** — запрос успешно обработан, тело ответа содержит запрошенные данные.
- **401 Unauthorized** — клиент не авторизован. Обычно требуется аутентификация (например, токен или API-ключ). В лабораторной работе мы возвращали 401 при отсутствии `?key=secret`.
- **404 Not Found** — запрошенный ресурс (маршрут, файл) не существует на сервере.

### 5. Чем `dotnet run` отличается от `dotnet watch run`?

- `dotnet run` — однократная сборка и запуск приложения. При изменении кода необходимо вручную остановить сервер (Ctrl+C) и снова выполнить команду.
- `dotnet watch run` — запускает **watcher** (наблюдатель за файлами). При любом изменении `.cs`, `.csproj` и др. сервер автоматически перезапускается, что ускоряет разработку.
